PDSDUET LOCAL DEPLOYMENT

Work from this PDSDuet source tree or an explicitly supplied local bundle. Do not download upstream OpenBot source or images to fill a missing installation. The original upstream licence and attribution remain intact.

RUNTIME
- Conversations, messages, tool calls/results, runs and reconnect events belong to the local PostgreSQL backend.
- Reuse the existing model connection and tool execution loop. Model credentials and application sign-in are separate operations.
- Google application sign-in, user roles, grants, audit, attachments and model OAuth remain application features.
- CopilotKit runtime, Intelligence project sign-in, gateway connections, private lock APIs and vendor telemetry are removed.
- Automatic learning, learned-skill delivery, cloud memory mirroring and semantic recall are removed.
- Do not add compatibility adapters, old-data import, backfill, dual-write or migration work.

CONFIGURATION
Start from `.env.example`. Configure DATABASE_URL, KEY_ENCRYPTION_KEY, the selected model credential and application sign-in. The OpenAI API path uses OPENAI_API_KEY. The existing model picker can use its supported API-key, subscription or compatible-endpoint path.

For shared access, configure the existing Google/Microsoft/Okta application sign-in settings and INITIAL_ADMIN_EMAILS. OPENBOT_SINGLE_USER=true gives every visitor one administrator identity and is only suitable for the explicitly chosen local mode.

LOCAL SOURCE ENTRY POINTS
The application is in `openbot/`. The root scripts delegate to its local start and stop scripts. A desktop bundle must already include the application source, docker-compose.yml and a container-images.json naming the images provided by that bundle. Missing bundle files are reported instead of downloading an upstream release.

Do not echo API keys, OAuth tokens, credential files or customer documents. Preserve the user's unrelated uncommitted changes.

EXECUTION BOUNDARY
A request to edit the application is not authorization to run tests, builds, services, browser acceptance, probes or API/DB exercises. Follow the user's current execution rules. Read source and configuration and report the unexecuted runtime layers accurately.
