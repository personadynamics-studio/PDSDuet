# 獨立結算流程與統一呼叫入口

2026-11-14。依使用者最新方向重寫同一工作的計畫。這是下一次實作契約；目前執行碼先停止修改，按已保存工作樹提交，不宣稱已整合完成或已運行。

## 目標與保留能力

最優先保留瀏覽器／電腦：原生登入狀態、頁面與檔案操作、畫面、人手接管。Bot 可見名單只有正式 profile roster 一個來源；Bot 能呼叫同伴；群聊直接保存真實作者。手動郵件／日曆、帳號及工作目錄隔離保留。

不繼續修補現有 runner／thread-store 的交叉責任。抽出一個執行擁有者、一個獨立結算模組，再將舊入口、寫入點與專用依賴沿引用整條移除。結算在現有服務進程內完成，不新增另一個服務、框架或 RPC 層。

## 固定兩個契約

### execute：唯一呼叫入口

輸入為已認證的呼叫者、明確 Bot、對話、實際輸入，以及必要時的真 parentRunId。入口建立真 runId，取得一次需要的對話資料並組裝模型及工具。聊天、群聊、Bot 互叫、獨立日程只呼叫此入口，不各自建 agent、裝 middleware、選另一個 Bot 或直接改完成狀態。

模型與工具執行只產生實際輸出、工具結果及結果種類。所有本系統提供的工具由同一服務端工具迴圈執行；介面只顯示正式訊息、畫面與真正的人手等待。

### settle：唯一結果寫入與結算擁有者

結算模組接收同一 runId 的真實輸出、作者及 completed／failed／cancelled／waiting 結果。串流記錄亦由此模組持有，其他入口不得另存一份正式對話。

最後結算在同一原生 DB 交易中保存尚未落地的輸出、終態或等待資料，以及供重連使用的事件。不先標完成再補交答案；不由原 Bot 再調模型轉述；不等待畫面 ACK、錄製、通知、審計旁務或背景工作才能交付。

結算錯誤回到唯一執行擁有者，不吞成成功、不另建補償佇列。已保存的部分輸出保留真實結果；進程中斷留下 interrupted，不能冒稱完成或自動重跑有外部效果的工作。

## 執行、等待與取消

以單一執行擁有者管理實際 run、工具及取消範圍，不承接舊多副本 queue／claim／續租機制。執行結束即移除其實際資源，不保留失敗物件作診斷。

Bot 互叫使用相同 execute／settle，回覆以真正 senderBotId 落在同一對話；普通群聊發言不先轉成工作。Stop 作用於實際執行及所屬子執行，結算為真取消；觀看斷線不等於取消。

人手問題、瀏覽器接管及私密輸入只保存原 toolCallId 與必要等待資料。人手答覆從正式對話恢復該呼叫及同批尚未完成的工具，不讀另一份完整 continuation snapshot，不依目前 UI 選中的 Bot 猜接收者。

## 拆除順序與範圍

1. 在獨立模組固定 execute／settle 及其責任，先不搬舊 wrapper、後備、修復 helper 或重試身份。
2. 聊天、群聊、Bot 互叫及日程全部改成直接呼叫；模型與工具結果只能進結算模組。
3. 沿 producer、caller、consumer 與設定，整條移除舊 runner／thread-store 中已被替代的執行、寫入與收尾路徑；不留雙軌、別名、flag 或假相容接口。
4. 拔除普通對話上的 work queue、claim、relay、審批／背景工作轉接、輪詢與專用 UI。Task、主動研究、Responsibility、通知與其他非核心域不再成為核心依賴。
5. 只讀核對來源及 diff；將代碼形狀寫入 dogshit，實作計畫與進度只留在 tasks／交付說明。

真正的認證、Bot／帳號可見性、連接器授權和檔案 containment 留在各自輸入邊界；內部沿型別契約傳遞，不反覆重驗同一事實。
